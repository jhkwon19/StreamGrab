# StreamGrab 0.2.0

## 목표

0.2.0은 표준 HTML만 처리하던 초기 CLI를 플랫폼과 보호 페이지까지 확장하는
버전이다. 사이트별 코드를 무작정 늘리지 않고, 정적 분석과 전문 백엔드의 책임을
분리하는 구조를 마련하는 데 초점을 맞췄다.

## 처리 흐름

```text
입력 URL
├─ YouTube URL → YouTube yt-dlp adapter
└─ 일반 URL
   ├─ 직접 미디어 URL → 기존 Direct/HLS downloader
   ├─ 정적 HTML에서 미디어 발견 → Generic Extractor
   └─ 네트워크 차단 또는 미디어 미발견
      └─ yt-dlp Generic + curl-cffi impersonation
         └─ iframe 내부 전문 extractor
```

## 주요 기능

### YouTube

- `youtube.com`, `youtu.be`, `youtube-nocookie.com`을 별도 backend로 분기한다.
- `--list-formats`로 native format ID, 해상도, FPS, 코덱과 알려진 크기를 표시한다.
- 기본적으로 최고 품질 MP4 영상과 M4A 음성을 선택해 FFmpeg로 병합한다.
- `-f '137+140'`처럼 yt-dlp 형식 조합을 그대로 지정할 수 있다.
- 의도하지 않은 playlist 다운로드와 기존 파일 덮어쓰기를 막는다.

### 보호·임베드 일반 페이지

- 가벼운 정적 분석을 항상 먼저 실행한다.
- 정적 페이지 요청이 실패하거나 미디어를 찾지 못할 때만 yt-dlp Generic
  fallback을 실행한다.
- Cloudflare challenge에는 curl-cffi가 제공하는 공식 브라우저 impersonation을
  사용한다.
- 외부 iframe이 Bunny CDN처럼 yt-dlp가 아는 플레이어라면 해당 전문 extractor에
  분석과 전송을 위임한다.
- CAPTCHA, 로그인, DRM 또는 접근 권한은 우회하지 않는다.

### 출력과 보안

- 분리된 영상·음성의 알려진 전체 바이트를 합쳐 하나의 0~100% 진행률로 표시한다.
- yt-dlp fragment 이벤트의 바이트 값이 초기화돼도 표시 퍼센트는 역행하지 않는다.
- 서명된 CDN URL의 query는 DEBUG 로그에도 남기지 않는다.
- 후처리와 병합 안내는 작업당 한 번만 출력한다.

## 런타임 요구사항

- Python 3.11 이상
- FFmpeg
- `yt-dlp[default,curl-cffi]>=2026.8.18.122307.dev0`
- YouTube의 전체 JavaScript challenge 지원에는 Deno 2.3 이상 또는 Node.js 22
  이상을 권장한다.

StreamGrab은 PATH를 먼저 확인하고 NVM에 설치된 지원 Node.js 중 가장 최신 버전을
자동 선택한다.

## 검증 결과

- YouTube: 1080p 영상과 한국어 M4A 음성을 실제 다운로드하고 MP4 병합 완료
- 보호 페이지: Cloudflare 응답 감지 후 iframe의 Bunny CDN HLS 형식 발견
- HLS: 1,768개 조각 중 첫 조각 테스트 전송 완료
- 자동화: `pytest` 33개 통과
- 패키지: `pip check` 통과

## 알려진 제한

- DASH downloader는 아직 없다.
- 로그인 세션과 브라우저 cookie 입력은 아직 지원하지 않는다.
- 여러 embedded video가 반환될 때의 선택 정책은 설계 중이다.
- playlist는 안전을 위해 기본 비활성화되어 있다.
- 사이트 변경에 따라 yt-dlp와 JavaScript 런타임 업데이트가 필요할 수 있다.

관련 설계 결정은 [ADR 0004](../decisions/0004-use-yt-dlp-for-youtube.md)와
[ADR 0005](../decisions/0005-ytdlp-generic-fallback.md)에 기록되어 있다.
